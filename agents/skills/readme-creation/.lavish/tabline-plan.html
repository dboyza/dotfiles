Selected design

Appearance

  • Rosé Pine palette from the existing terminal configuration.
  • Top bar, visible even with one native tab.
  • Rounded caps and active tabs; no pointed separators.
  • Separate battery and hostname capsules with clean, fully rounded ends.

Information

  • Mode and WezTerm workspace on the left.
  • Compact numbered native tabs in the middle.
  • RAM, CPU, clock, battery, and hostname on the right.
  • Secondary details hide progressively in narrow windows.

Planning is complete. These choices have been recorded; implementation has not been requested.

Implementation plan

1. Replace the visual layout

Configure Tabline sections A/B as mode and workspace, tabs in the middle, X as RAM/CPU, Y as clock/battery, and Z as hostname. Use rounded Powerline half-circle glyphs from the installed Nerd Font for tab and section boundaries. Render battery and hostname as separate capsules with full semicircular ends and a one-cell gap, so their backgrounds never meet at a square edge. Keep inner component separators subtle, with no pointed arrows. Display the mode label in lowercase to match the reference.

2. Preserve useful naming

Keep explicit names, Unicode-safe truncation, and the 24-cell tab maximum. Replace fixed-width centered labels with compact labels, using the working directory for active tabs and process names for inactive tabs.

3. Give Tabline ownership

Remove the resize and reload callbacks that clear the left status, since they would erase the new mode and workspace sections. Keep the 0.8 window opacity and default text colors. Avoid Tabline's broad apply_to_config helper.

4. Handle small windows

Reserve space for tabs first. Hide RAM/CPU below 140 columns, shorten the hostname below 120, then hide hostname and workspace below 100. Below 80, show tabs and a compact mode indicator. Hide battery if no battery is reported.

5. Keep platform handling explicit

Use the plugin's platform branches for metrics, with Windows PowerShell/CIM enabled instead of legacy WMIC. Throttle metrics to five seconds and omit unavailable values. Evaluate whether sampling causes visible UI delays before enabling it permanently.

6. Validate and record

Check actual WezTerm formatting, short and Unicode tab titles, one and many tabs, all modes, narrow widths, and unavailable metrics. Run existing key and launch-size tests. Update repository guidance for the approved visibility and left-status behavior, then commit locally.

Selected direction

Use the rounded reference layout with Rosé Pine accents, a top bar, and single-tab visibility. This will be visible while you work in Herdr, at the cost of an additional terminal row.

Native Windows and WSL execution need platform validation; this machine can validate the macOS path. The current installed plugin has platform metric implementations, but their sampling methods differ.
